# ガシャガシャ！おもちゃドラム — 実装仕様書

作成日: 2026-11-06  
プロジェクト: child_games / 対象: PCで遊ぶ4歳児  
URL案: `/games/toy-drum`  
状態: 実装前の仕様案。以下の時間・件数・音量は初期値であり、実機試遊で調整する。

## 1. このゲームで届けたい体験

適当にキーボードを打つと、そのたびに動物が楽器をたたき、音と動きが返ってくる。ゆっくりなら一音ずつ、ガシャガシャ打てば小さな大騒ぎ。「自分の手でこの音を出している」という感覚を中心にする。

正解のキー、リズム判定、点数、失敗、制限時間は設けない。既存の「どうぶつバンド」はメンバーを選んで演奏を組む遊びとして残し、本作は押す行為そのものを楽しむ独立したゲームにする。

## 2. 初回リリースの範囲

- 1ステージ、5頭の動物、5系統の楽器音。参加メンバーの選択は不要。
- 通常打鍵、連打、同時押し、長押しに異なる反応。
- 操作中だけ流れる控えめな伴奏と、動物の掛け合い。
- クリック・ポインター長押しでも遊べる5つの大きな楽器パッド。
- 音量・ミュート・音声案内・動きを抑える共通設定。
- 終了操作をするまで自由に遊べる。1回の完成条件は作らない。

録音、楽譜、曲選択、マイク、オンライン共有、外部音楽APIは含めない。新規画像・音は実装段階で用意し、本書では既存素材の流用可能性を示す。

## 3. 画面と初回30秒

上に「どこを おしても おとがでるよ」、中央に5頭と楽器、下に5つのパッドと小さなキーボード図を置く。1280×720と1366×768でステージとパッドが収まる構成を基準とする。設定・ホームは遊びのパッドと離して置く。

「あそぶ」を押すと舞台へフォーカスを移す。最初から全員が見え、どの対象キーでも一音目が鳴る。最初の打鍵で、その動物の手・楽器・音符が同時に反応する。数回押すと隣の動物が体を揺らすが、自動演奏が操作音を埋めない。説明を閉じる操作やチュートリアルの正解を要求しない。

最初の30秒で「押すと鳴る」「速く押すとにぎやか」「手を離すと静か」の3つを体験できることを目指す。8秒操作がなければ1頭だけがそっと手を振る。催促の音声や自動打鍵は出さない。

## 4. 入力の共通契約

本節はペンキ・つみきタワーにも同じ内容で適用する。実装時は共通の `useMashInput` にまとめる。

| 入力 | 扱い |
| --- | --- |
| 英字・数字・記号の物理キー、テンキー、矢印、Space、Enter、Backspace、Delete | 舞台にフォーカスがある間は遊びに使う。Enterでも終了しない |
| Shift単体 | 遊びの発火なし。他の通常キーとの併用は許可 |
| Tab／Shift+Tab | 標準のフォーカス移動を維持。舞台を離れたら長押しを解除 |
| Escape | 共通の一時停止を開く。作品や状態は消さない |
| Ctrl・Command・Altとの組み合わせ、ファンクションキー、OS専用キー | 奪わない。ゲームの発火対象外 |
| 日本語入力の変換中、入力欄、設定・一時停止画面 | 遊びの入力処理を停止。`isComposing`などで判定 |

対象キーは `KeyboardEvent.code` の明示的な一覧で定義する。配列は固定し、未定義のキーにハンドラを広げない。JIS/US配列で記号の表示が違っても、文字入力を要求しない。OSやブラウザが予約しているキー、キーボードが検出できない多重押しまで扱えるとは案内しない。

通常打鍵は、押されていなかったキーのkeydownを1回と数える。keyup後の押し直しはすぐ受け付ける。OSの `event.repeat` は音の追加発火に使わず、長押しはゲーム内の時計で生成する。

80ms以内に3つの異なる対象キーの新しいkeydownが届いたら同時押し演出を1回追加する。通常の1打目は80ms待たずに反応する。同じキーのrepeatや、押しっぱなしのキーは同時押しの新規入力に数えない。特別演出の再発火は最低1秒空け、その間も通常の打鍵は受け付ける。同時押しが検出できなくても全ての基本体験が成立する。

舞台はフォーカス可能にし、開始・再開・楽器パッドのポインター操作後にフォーカスを戻す。Tabで操作している時はパッドにフォーカスを保ち、Enter/Spaceの標準クリックだけを発火させる。舞台のキー処理とボタンのクリックを二重に発火させない。ホームや設定にフォーカスがある時は通常のUI操作を維持する。

## 5. 楽器と操作への反応

| 物理キーの主な範囲 | 動物・音 | 動き |
| --- | --- | --- |
| 数字上段・テンキー数字 | ゾウの太鼓：ポン、ドン | 太鼓の皮と耳が沈んで戻る |
| Q〜Pの段と周辺記号 | ウサギのベル：チリン、キラリン | 耳が跳ね、丸い星が出る |
| A〜Lの段と周辺記号 | クマの木琴：コロン、ポロン | 手元から色の丸が転がる |
| Z〜Mの段と周辺記号 | ペンギンのラッパ：ぷぅ、ぱぁ | 頬とラッパが伸び縮みする |
| Space・Enter・矢印・削除キー・残りの対象記号 | サルのおもちゃシンバル：パシャ、カシャ | 紙のリボンと小さな輪が広がる |

実装時のキー定義は上記の優先順で全対象キーを一度だけ割り当てる。キーごとに音の高さや動きの方向を固定し、微小な音色差だけを変える。同じキーでも毎回別の動物になるようなランダム化はしない。

- 直近600msに通常打鍵が5回以上あると「はしゃぎ」へ入り、動物の身振りを大きくする。2回以下の状態が500ms続けば通常へ戻す。音量は増やさない。長押しの自動発火は打鍵回数に含めない。
- 同時押しでは全員が1回跳ね、丸い音符の輪を出す。通常打鍵の音に加えて大音量の効果音を重ねない。
- 300msの長押しで、太鼓・木琴・ベル・シンバルは毎秒6回までの連続奏法へ移る。ラッパは短い音から持続音へ滑らかにつなぐ。手を離すと持続音を80ms以内のフェードで止める。
- 複数長押しの連続発音は全体で毎秒12回まで、持続音は2声まで。上限を超えたキーは音を重ねず、対応する動物の動きへまとめる。
- 画面のパッドは対応楽器の打鍵・長押しを再現。クリックだけでも楽しさが成立し、同時押し専用の進行条件は作らない。

## 6. 音を気持ちよくする仕組み

操作音は次の拍まで待たせず即時に開始する。伴奏だけを96 BPMの共通クロックに乗せ、音程がある楽器はC・D・E・G・Aの音群を中心にする。ランダムな入力を譜面へ変換する機能は初回には作らない。

伴奏は最初の打鍵後に小さく入り、全キーとポインターを離してから1.5秒入力がなければ300msで消える。休んでいる間に演奏を続けない。打鍵直後の視覚反応は次の描画フレーム、操作音の体感遅延は対象PCで100ms以内を目標とする。実測値とブラウザを記録し、全端末での保証値にはしない。

同時発音は短音・持続音・伴奏を含め12声を上限とし、超過時は古い短音をフェードして新しい操作音を優先する。イベントの待ち行列を伸ばさない。1フレーム内の同楽器の大量入力は1回の厚みのある反応にまとめる。共通音量に従い、マスターへ余裕を残したゲインとピーク抑制を設ける。最大密度でも音割れや刺さる高音がないか実際に聞く。

音声案内は開始時の1回と明示的なヘルプのみ。打鍵ごとに `speechSynthesis` を呼ばない。ミュートでも5頭の動きと音符の形で違いを楽しめる。

## 7. 進行・終了・一時停止

| 状態 | 遷移と動作 |
| --- | --- |
| `ready` | あそぶで音を初期化し、舞台へフォーカスを移して`playing`へ |
| `playing` | 入力の強さに応じて通常／はしゃぎを切り替える。勝手に完了へ進まない |
| `paused` | 設定・Escape・タブ移動・ウィンドウのフォーカス喪失で音と時計を止める |
| 再開 | つづきからあそぶで`playing`へ。押下集合・同時押し窓・連打計数は空にする |
| 離脱 | ホームへの明示操作で予約音・持続音・イベント・描画処理を破棄する |

再開後は新しく押したキーだけを使い、休止前の長押しは復元しない。音の初期化が失敗しても視覚で遊べ、設定に音の再試行を用意する。ポインターのup・cancel・キャプチャ喪失でも長押しを解除する。

動きを抑える設定ではジャンプ・揺れ・飛び出す音符を止め、手のポーズ変更と穏やかな枠表示に置き換える。フルスクリーンの点滅やカメラ揺れは通常設定でも使わない。

既存 `Art.tsx` の動物を流用し、新しい楽器はSVGで足す。位置と縮尺を持つ外側要素とアニメーションする内側要素を分ける。既存バンドで修正した「動物から楽器が離れる」問題を再発させない。

## 9. 実装構成と上限

- 画面案: `src/games/ToyDrum.tsx`。`src/data.ts` と `src/App.tsx` に新しいゲームを登録する。
- 共通入力案: `src/mash.ts`。`useMashInput` は正規化済みの打鍵・解放・同時押し・長押しを返す。既存 `useKeys` の対象キーを全ゲームへ一律拡張しない。
- `DrumState`: phase、heldCodes、lastHitByInstrument、density、energyMode、chordCooldown、activeVisuals。
- 音源管理案: `src/toyDrumAudio.ts`。既存のAudioContext・masterを共有し、ゲーム専用の音源集合と停止処理を持つ。既存 `audio.band()` をそのまま使う前提にはしない。
- 音符は最大60個、寿命1秒程度。超過時は古い装飾を置換。入力履歴は直近600ms分だけ保持する。
- 共通 `GameShell` に自由遊び用の案内と舞台フォーカスを追加する。既存 `finish()`・完了紙吹雪を自動的に呼ばない。既存11ゲームの終了操作は変更しない。

## 10. 受け入れ条件

1. 開始後、対象キーのどれから押しても即時に音と視覚反応がある。Enter・Space連打で終了・再開始しない。
2. 同じキーの押し直しを数え、OS repeatは通常打鍵に加算しない。長押しはOSのリピート設定に左右されない。
3. 同時押しは80ms窓・3キー・1秒の再発火間隔を守り、1打目の応答を遅らせない。
4. 長押しを離す・一時停止する・ホームへ戻ると、持続音が残らない。
5. 通常キーを毎秒20回相当で30秒入力しても、発音数・音符数・予約数が上限内。手を止めた後に溜まった打鍵を再生しない。
6. 5分の自由演奏でオブジェクトや音源ノードが増え続けない。上限到達後も新しい打鍵が見える。
7. Tabで全パッド・設定・ホームへ移動でき、Enter/Spaceで各ボタンが一度だけ動く。
8. クリックのみ、ミュート、動きを抑える設定でも遊べる。画面サイズごとの見切れを確認する。
9. JIS/US配列、IME変換、2〜5キーの同時押し、ブラウザの予約キーを実機で確認し、検出できない組み合わせを記録する。
10. Chrome・Safari・Edgeの確認状況と、実際に聞いた音量・音割れ・遅延を記録する。DOMテストだけで聴感確認済みとはしない。

## 11. 試遊と改善の判断

最初は一音ずつ、次に左右の手で適当に連打し、最後に長押しと手放しを試す。音の違いが分からなければ音色と動物の動きを離し、騒がしいだけなら発音密度と伴奏を減らす。反応が鈍いなら音を拍へ寄せず、即時反応の経路を短くする。

子どもとの試遊では、説明なしで押し始めるか、音を聞くために自分から止まるか、別の場所へ手を移すかを観察する。速く打てることは評価しない。手の力を強くするよう促さず、軽いタッチでも同じ反応を返す。

## 12. 実装順序と公開

1. 共通入力と仮の5パッドで通常打鍵・同時押し・長押し・解除を検証。
2. 1楽器の即時発音と音源上限・停止処理を作り、連打して聴感確認。
3. 5楽器と動物、はしゃぎ、伴奏を追加。
4. 舞台フォーカス、設定・再開・離脱、クリック操作を統合。
5. 既存ゲームのキー操作に影響がないことを確認し、実ブラウザ試遊で調整。

## 13. 後回しにする拡張

楽器の着せ替え、季節の舞台、保護者が任意に開始する短い録音を候補とする。曲数よりも「押した瞬間の音と、止めた瞬間の静けさ」を先に磨く。
