# どばどば！にじいろペンキ — 実装仕様書

作成日: 2026-11-06  
プロジェクト: child_games / 対象: PCで遊ぶ4歳児  
URL案: `/games/rainbow-paint`  
状態: 実装前の仕様案。時間・数・大きさは初期値として試遊で調整する。

## 1. このゲームで届けたい体験

キーボードを適当に打つだけで、白い紙に「べちゃっ！」と絵の具が飛ぶ。連打すると花火のように広がり、押しっぱなしにすると線がにょろにょろ伸びる。何を描くか決めなくても、自分の手から色と形が生まれ続ける。

見本、正解、塗り残し判定、点数、失敗、制限時間は設けない。「汚してよい」「偶然できた形がおもしろい」を体験の中心にする。ドラムが音、タワーが崩れる動きを主役にするのに対し、本作では入力の跡が作品として残る。

## 2. 初回リリースの範囲

- 1枚の自由なキャンバス、6色、丸・星・しぶき・渦巻きの4系統。
- 通常打鍵、連打、同時押し、長押しで変わる描き方。
- 模様をもらいに来る車と恐竜の2種類のゲスト。
- 任意の「まっさら」と、直前の紙1枚へ戻る操作。
- 大きな画面パッドと、キャンバスのクリック・長押し。
- 共通の音量・ミュート・音声案内・動きを抑える設定。

色や筆を先に選ばせない。ファイル保存・自動ダウンロード・端末をまたぐ作品保存・画像アップロード・オンライン共有は初回に含めない。紙の内容はセッション内だけで保持し、ホームへ戻ると破棄する旨を保護者向け説明へ記載する。

## 3. 画面と初回30秒

中央の白い紙がステージの大部分を占める。下に色と形を示す4つの大きな遊びパッドを置き、右上に紙を替える絵、直前の紙の小さなサムネイルを置く。ゲストは画面下の専用通路を歩き、入力パッドや作品の中央を覆わない。

開始後の案内は「どこを おしても ぺんきがでるよ」。最初の1打は中央付近へ大きめのしぶきを出し、以後は紙全体へ広がる。5秒以内に派手な演出がなくても、一つの点をじっと眺めてよい。説明を読み終える待機や、特定キーを押す課題は挟まない。

30秒以内の自由な入力で、点が増える・線が伸びる・ゲストが模様をまとって帰る流れを経験できることを目標とする。操作が少ない場合にゲストを見ることを必須にしない。

## 4. キー・ポインター入力

[おもちゃドラム仕様書の「入力の共通契約」](11_TOY_DRUM.md#4-入力の共通契約)を適用する。英字・数字・記号・矢印・Space・Enter・削除キーを遊びに使い、EnterやBackspaceでも完成・消去しない。TabはUI移動、Escapeは一時停止。Ctrl・Command・Altの組み合わせやOS予約キーは奪わない。IME変換中と入力欄では描画しない。

舞台フォーカス中だけキーを処理し、開始・再開後にフォーカスを戻す。Tabでボタンを選んでいる間は標準のEnter/Space操作を維持する。画面ボタンのクリックと舞台の打鍵を二重に数えない。

| 操作 | 紙に起きること |
| --- | --- |
| 通常打鍵 | 固定のキー定義に対応する色・形が1つ出る。次の打鍵で位置を少し変える |
| 直近600msに5打以上の連打 | 新しい形の周りに小さなしぶきを増やす。3倍の描画件数にはせず、一つの模様として描く |
| 80ms以内の異なる3キーの新規押下 | 通常の跡に加えて大きな「混ざりしぶき」を1つ。再発火は最低1秒空ける |
| 300ms以上の長押し | 最後の着地点から太い線が伸びる。全長押し合計で毎秒10区間まで |
| キャンバスのクリック・長押し | 触れた場所を始点に同じ描画。細かなドラッグは不要 |
| 下の4パッド | 対応形を紙の中へ描く。長押しで線も出る |

OS repeatは通常打鍵として数えない。長押しは押下集合とゲーム内時計で生成し、keyup・pointerup・pointercancel・フォーカス喪失で解除する。同時押しが検出できなくても遊びに不足が出ない。連打状態は通常打鍵が600ms内に2回以下のまま500ms続いたら解除する。

## 5. 色・形・位置のルール

色はピンク、黄、青緑、青、紫、オレンジの6色。高密度でも黒や灰色へ濁らない塗り方にする。形の輪郭と白い縁取りにより、既に塗られた場所にも新しい入力が見える。

`PaintKeyDefinition` にキーごとの色・形・基準位置を固定する。上段・中段・下段は紙の上・中・下へゆるく対応し、Space・Enter・矢印は紙の中央付近の大きな丸を使う。意味を覚えなくても遊べ、同じキーを試すと似た結果を得られる。

- 1打の模様は紙の短辺の8〜16%程度。位置は基準位置の周辺で循環させ、同じキーの連打で一点だけを覆わない。
- 同時押しは短辺の25〜35%程度の模様。押されたキーの最大3色を並べ、単純な色の平均で濁らせない。
- 長押しの線は少しずつ曲がり、端へ来ると内側へ向きを変える。キーごとに曲がり方を固定し、最長3本の線を同時に見せる。4キー目以降は既存の線へ色の節を加える。
- 同じフレームに大量入力が来た時は近い跡を一つの模様へまとめ、色と大きさへ反映する。画面外へ描画せず、手を止めた後に遅れて大量の絵の具を落とさない。
- 書き込み済みの紙は自動で消さない。長く遊んで重なっても、縁取りと形の差で新しい跡を追えるようにする。

## 6. 模様をもらうゲスト

初回は通常打鍵12回以上かつ遊び始めて8秒以上で、最初のゲストが現れる。条件を満たした時の直近3秒に入力がなければ、次の入力を待つ。以後は前のゲストの退場から最低20秒空け、次の入力時に車・恐竜を交互に出す。

ゲストは一度に1体、滞在約5秒。到着時の紙の模様を小さな画像へ複写し、車体または恐竜の体のマスク内へ貼る。「ぬってくれて ありがとう」の身振りをして帰る。作品の絵の具を奪ったり、通路へ描くために操作先を切り替えたりしない。

ゲストの出入り中も通常の描画を受け付ける。ゲストは自動的に絵を追加しない。音声は毎回しゃべらせず、短い効果音と見た目だけで伝える。コピー画像は退場時に解放する。

## 7. 紙替え・進行・一時停止

| 状態・操作 | 動作 |
| --- | --- |
| `ready` → あそぶ | 音を初期化し、白い紙で`painting`へ。舞台にフォーカス |
| `painting` | 描画・ゲストを並行して更新。自動終了しない |
| まっさら | 現在の紙を直前の紙として1枚保存し、新しい白紙へ。古い「直前の紙」は置換 |
| まえのかみ | 現在の紙と直前の紙を交換する。何度も交換して見比べられる |
| `paused` | 設定・Escape・タブ移動・フォーカス喪失で線・しぶき・ゲスト・音を停止 |
| 再開 | 紙とゲスト位置は保持。入力の押下集合と連打・同時押し判定はリセット |
| ホーム | 音・予約・画像・Canvasを解放。紙は端末へ保存しない |

紙替えは画面上の明示操作だけに割り当てる。絵のない白紙も選べる。紙替え中の長押しは解除し、紙替え前に押されていたキーは離して押し直すまで描画に使わない。ボタンのキーボード操作を終えて舞台へ戻る手段を用意する。紙を替えても、既にゲストがもらった模様はその退場まで保つ。

音が出ない場合も描画を継続する。動きを抑える設定では飛来・飛散・にょろにょろ移動を止め、通常打鍵で完成形を即時表示し、長押しは毎秒3回までの隣接する模様の追加へ置き換える。ゲストは位置移動の代わりに静止した登場・退場表示にする。

## 8. 素材と音

| 分類 | 必要なもの |
| --- | --- |
| 紙・UI | 白い紙、紙替え、前の紙、4パッド、ホームカード |
| ペンキ | 4系統の形、白い縁、小さなしぶき。CanvasパスまたはSVGで定義 |
| ゲスト | 車と恐竜の体・輪郭・目・手足。体の模様用マスク |
| 音 | べちゃ、ぽた、しゅる、短いゲスト音、開始案内 |

既存SVGの車・恐竜から必要な部品を流用する。外部画像・フォント・画像生成APIをプレイ中に読み込まない。音は短い柔らかな合成音を基本にし、描画イベントごとに必ず別音源を作る設計にはしない。

効果音の開始は全体で毎秒10回、同時発音8声を上限とする。超過時は音をまとめ、新しい視覚反応を優先する。入力密度でマスター音量を上げない。長押しの音はキー解放時に短くフェードし、入力を止めると余韻を除いて静かになる。常時BGMは初回には付けない。

## 9. 実装構成とメモリ管理

- 画面案: `src/games/RainbowPaint.tsx`。共通 `useMashInput` と `usePlay` に接続する。
- キャンバスはCanvas 2D、操作UIとゲストの枠はReact/SVGで構成。Reactに全描画点を保持しない。
- `PaintState`: phase、paperId、paletteMap、activeStrokes、inputDensity、guest、previousPaperAvailable。
- `PaintEngine`: 基礎画像、直近の描画命令、現在の紙、前の紙、ゲスト用縮小画像。
- 基本座標は900×420。表示比率を保ち、ポインター座標は表示矩形から変換する。解像度倍率は最大2、描画面1枚は最大1800×840相当とする。
- 描画命令は200件で基礎画像へ焼き込み、古い命令を解放する。見た目の跡は残し、履歴配列を無制限に伸ばさない。空の紙を含め、現在と直前の2枚だけを保持。
- 動くしぶきは最大80個・寿命600ms、線は最大3本。ゲスト用画像は1枚だけ。上限時は古い装飾を置換する。
- リサイズ後も同じ紙を再描画し、勝手に白紙へ戻さない。画像のコピーは紙替え・ゲスト登場時だけとし、毎打鍵で画像全体を複製しない。

## 10. 受け入れ条件

1. 対象キーのどれでも初回から跡が出る。色・形・位置の基本対応が固定されている。
2. 連打しても新しい跡が見え、音量や描画待ち時間が増え続けない。Enter・削除キーで紙を失わない。
3. OS repeatを通常打鍵へ加算せず、長押しで線が伸び、離した時に止まる。
4. 同時押しの基本条件と上限を守る。同時押し未対応のキーボードでも通常打鍵・長押しで楽しめる。
5. 5分間描いても、紙2枚・命令200件・線3本・しぶき80個・ゲスト1体の上限を守る。焼き込み時に跡が消えない。
6. まっさら→まえのかみで元の紙へ戻れる。リサイズ・一時停止で作品を失わない。
7. ゲストの模様は登場時の紙と対応し、退場まで変わらない。作品を消さず、操作を止めない。
8. ミュート・動きを抑える設定・クリックのみ・Tab移動で全ての基本操作ができる。
9. 1280×720、1366×768、1024×768で紙・パッド・終了導線を確認。座標ずれと見切れがない。
10. Chrome・Safari・Edge、JIS/US配列、IME、連打毎秒20回相当で30秒、長押し10秒後の離脱を確認し、実施環境を記録する。

入力正規化・描画上限・紙の交換を小さな自動テストで確認し、色の重なり・塗った手応え・ゲストの模様は実ブラウザで評価する。

## 11. 試遊と改善の判断

大人の試遊では一つのキーだけ、両手の連打、複数長押し、同じ紙へ5分描く操作を順に試す。色が埋もれる場合は自動消去を足す前に輪郭と着地点を改善する。紙を見る前にゲストへ注意を奪われる場合は登場間隔を広げる。描画が遅れる場合は装飾と解像度を落とし、新しい入力の反応を優先する。

子どもには描く題材を指定せず、キーを変えて形を確かめるか、出来た模様を指さすか、手を止めて眺めるかを観察する。紙替えに気付かなくても、そのまま遊べることを重視する。

## 12. 実装順序と公開

1. 共通入力とCanvasで、一打の跡・固定のキー対応・ポインター座標を作る。
2. 連打・同時押し・長押しと描画上限、焼き込みを実装。
3. 紙2枚の交換、リサイズ・中断・離脱時の処理を確認。
4. ゲスト2種類と模様の複写、控えめな音を追加。
5. 実ブラウザで5分試遊し、色・形・密度を調整してホームに登録。

本書は仕様の作成のみ。実装・公開は別工程とし、対象PRへのユーザー承認なしにマージ・自動マージ・例外操作をしない。

## 13. 後回しにする拡張

任意のPNG保存、紙の種類、ゲストの追加を候補とする。保存機能は保護者が明示的に使う形にし、連打でダウンロードが始まるキー割り当ては作らない。
