# へんしん！おしゃれモンスター — 実装仕様書

作成日: 2026-11-04  
プロジェクト: child_games / 対象: PCで遊ぶ4歳児  
URL案: `/games/monster-dressup` / 状態: 実装前の仕様案。選択肢数・演出は試遊で調整する。

## 1. このゲームで届けたい体験

キーを押すたびに、目が3つになったり、髪が雲になったりする。「こんな顔になっちゃった！」という笑いから、自分だけのキャラクターへの愛着につなげる。

完成ボタンを押すと、自分が選んだ格好のままモンスターがランウェイを歩く。途中でつまずいても転ばず、くるんとポーズに変えて観客を喜ばせる。見た目を評価するゲームにはせず、どの組み合わせにも同じ歓迎を返す。

面白さの核は、即座に見た目が変わること、予想外の組み合わせ、作った子が生きているように反応すること。

## 2. 初回リリースの範囲

- 基本の体型1種類。体色5色、目・口・角・髪・服・模様の6カテゴリ。
- 各カテゴリ4候補。「何も付けない」も一部カテゴリの候補に含める。
- ランダム変身、操作の取り消し、何度でも見られるリアクション。
- 約12秒のお披露目と記念ポーズ。1回2〜5分、編集時間は無制限。
- 名前入力、写真取り込み、作品の共有、ランキングは初回に含めない。

「男の子用／女の子用」や正解のコーディネートは設けない。

## 3. 画面・見た目

| 場面 | 内容 |
| --- | --- |
| ホーム | 目が3つの丸いモンスターと着替え道具のカード |
| おしたく部屋 | 中央に大きなモンスター、下に6カテゴリ、横に体色と取り消し |
| ランウェイ | 選んだ姿で歩き、観客の前で3回ポーズ |
| 記念写真 | キャラクターを拡大。「またへんしん」「もういちどあるく」「ホーム」 |

キャンディ色の更衣室と、星形の鏡。モンスターは丸く、牙や爪を怖くしない。色とパーツの輪郭をはっきり分ける。待機中はまばたき、呼吸、小さな手の動きを入れ、操作していない時にも存在感を出す。

## 4. 進行と状態

| 状態 | 入力・条件 | 反応と次の状態 |
| --- | --- | --- |
| `ready` | 再生 | 基本の姿が鏡の後ろから登場。`editing`へ |
| `editing` | 1〜6、←→、0 | 対応する見た目を即時に更新 |
| `editing` | Space／遊ぶ | 現在のパーツに応じた短いリアクション |
| `editing` | Enter／できあがり | 見た目のスナップショットを取り`runway`へ |
| `runway` | 約12秒 | 歩く→くるん→ポーズ→拍手。`complete`へ |
| `complete` | また変身 | 見た目を保持して`editing`へ |
| `complete` | もう一度歩く | 同じ見た目で`runway`へ |

初期の姿のままでも完成できる。ランウェイ中に数字を押しても見た目を変えず、記念写真が途中で別の姿にならないようにする。

## 5. キーボード・クリック操作

| キー | 内容 | 候補の例 |
| --- | --- | --- |
| 1 | 目を次へ | まるい目、3つ目、眠そうな目、星形の瞳 |
| 2 | 口を次へ | にっこり、丸い口、波形の口、小さな歯 |
| 3 | 角を次へ | なし、丸い角、くるくる、短い2本 |
| 4 | 髪を次へ | なし、もこもこ雲、くるん前髪、虹の毛束 |
| 5 | 服を次へ | サロペット、マント、水玉シャツ、宇宙服風 |
| 6 | 模様を次へ | なし、星、水玉、しましま |
| ←／→ | 体色を前後へ | ピンク、黄色、ミント、紫、空色 |
| 0 | おまかせ変身 | 全カテゴリと体色を一括で変更 |
| Space | 遊ぶ | 現在の姿で短い仕草 |
| Enter | お披露目 | ランウェイへ |

各カテゴリの大きな絵カードを押しても次の候補に切り替わる。現在と次の候補を小さな絵で示し、循環操作を分かりやすくする。長押しリピートは無視する。取り消し・基本の姿へ戻す操作は画面ボタンとTab移動で使える。

## 6. 変身とリアクションの細則

- 変身は100〜200ms程度の小さな弾みで即座に反映。長い煙で毎回顔を隠さない。
- 目が増えると順番にまばたき、雲の髪は頭を振ると小さな雲が浮く、マントはくるっと広がる。パーツを変えた瞬間に1回だけ特徴を見せる。
- Spaceの仕草は現在の口・服などから候補を選ぶ。歌う、くしゃみして星が出る、踊る、照れて手を振るなど、怖くない反応にする。
- リアクション中も編集可能。新しい操作を優先し、前の演出を終了させる。複数の顔アニメーションを積まない。
- 角・髪・服が重なっても顔が完全に隠れないよう、取り付け位置と描画順を固定する。
- ランダム変身は前と完全に同じ組み合わせを避け、1操作として取り消せる。音声で当たり外れを言わない。
- 取り消し履歴は最大30操作。やり直しボタンは不要とし、基本の姿へ戻す操作も1回で取り消せる。
- ランウェイでは同じ姿を保ち、最後に正面の静止ポーズを十分見せる。完成演出の長さは全組み合わせで同じ。

## 7. 必要な素材

| 分類 | 内容 |
| --- | --- |
| 本体 | 色替え可能な体、手足、顔の基準座標、歩く・回る・決めポーズ |
| パーツ | 6カテゴリ×4候補。角と髪の「なし」は透明定義。体の模様マスク |
| 部屋 | 鏡、着替え棚、星形の床、ランウェイ、観客 |
| 演出 | 雲、星、回転の軌跡、紙吹雪、記念フレーム |
| UI | カテゴリの絵、体色、キー図、サイコロ、取り消し、基本の姿 |
| 音 | 変身、パーツ別の短い反応、足音、拍手、完成音、案内、BGM |

体色はマスクまたはSVGの塗りで変える。パーツの原点、反転時の向き、影の位置を統一し、透過WebP/PNGを使う。顔の変化は差分素材とCSSで作り、毎回画像を生成しない。

## 8. 技術構成とデータ

React + TypeScript + Vite、DOM上のパーツ合成とCSSアニメーションを基本にする。

- `Appearance`: bodyColorId、eyesId、mouthId、hornsId、hairId、outfitId、patternId。
- `MonsterState`: phase、appearance、history、reactionId、runwaySnapshot、paused。
- `PartDefinition`: category、id、assetUrl、anchor、zIndex、reactionId、thumbnail。
- 描画順は体→模様→服→口→目→角→髪を基本とし、部品単位で調整できる。
- リアクションと見た目の状態を分離し、動作を止めても選択を失わない。
- 出力した見た目の組み合わせを検証できるよう、ID集合と取り付け座標を定義に集約する。

配置案: `src/games/monster-dressup/{MonsterDressupGame.tsx,reducer.ts,parts.ts,reactions.ts,components/,styles.css}`。素材は`public/assets/monster-dressup/`。初期版は作品を保存せず、共通の音設定だけ端末内保存する。

## 9. 子供向けUI・中断・読み込み

キャラクターを大きく保ち、1366×768で全カテゴリが見える。クリック対象は64px以上が目安。案内は「めをかえてみよう」「できあがったら あるこう」などの短いひらがなと音声。

設定・タブ移動・フォーカス喪失で演出と音を一時停止。復帰時は再開ボタンを待つ。キーの押下状態を消し、ホームへ戻る時は演出と音を破棄する。全パーツを先読みし、読み込み失敗時は再試行する。ミュートでも変身とお披露目が分かる。

## 10. 受け入れ条件と確認

1. 各カテゴリが4候補で循環し、体色5色と独立して変わる。
2. すべてのパーツ組み合わせで顔が認識でき、極端な重なりがない。
3. おまかせ変身と基本の姿への復帰を1操作で取り消せる。
4. 編集中にリアクションを連続発火しても状態が壊れない。
5. 完成時の見た目とランウェイ・記念写真が一致する。
6. 初期状態でも完成でき、見た目による採点が出ない。
7. キーボードだけ／クリックだけで変身から再プレイまで進める。
8. 音なし、一時停止・復帰、ホーム再訪で正しく動く。
9. ランダム生成と履歴上限でメモリや描画が増え続けない。
10. Chrome・Safari・Edge、表示倍率を確認し、実施環境を記録する。

候補循環・履歴・ランダム生成はユニットテスト。パーツ単独と、角・髪・服の重なりやすい組み合わせをブラウザで確認する。試遊では「変えて戻す」「お気に入りを自分で決める」「同じ子をまた歩かせる」を観察する。

## 11. 実装順序と公開

1. 本体と各パーツの基準位置をそろえ、静的な合成画面を作る。
2. 6カテゴリ・体色の切り替え、おまかせ、履歴をつなぐ。
3. 表情とパーツ固有のリアクションを加える。
4. 現在の姿のまま歩くランウェイと記念画面を作る。
5. 本番画像・音、先読み・中断・再訪を確認する。
6. 試遊で候補数と演出時間を調整し、ホームに登録する。

GitHub + Cloudflare Pagesを候補とし、`npm run build`の`dist`を配信。プレビュー確認後mainへ反映し、直接URLの再読み込みも確認する。本書作成では実装・公開を行わない。

## 12. 将来の拡張と守ること

体型の追加、背景変更、短い音声の名前、作品の画像保存を候補とする。パーツを増やすときも、「変化が見える」「どの見た目も歓迎される」「自分で選んだ姿で動く」を守る。

## 13. 初回30秒の演出と試遊での判断

最初のモンスターは、目2つ・小さな笑顔・角なし・髪なしのシンプルな姿にする。1の最初の切り替え先を3つ目にして、押したら大きな違いが出る。増えた目が順番にまばたきして、鏡の中の自分を見て驚く。変身後のパーツはすぐ見えるよう、煙で隠さない。

その後は髪や服を指す説明を重ねず、自由に押せるようにする。Spaceの絵はモンスターが手を振る動きに合わせて出し、「つくるだけでなく、この子と遊べる」と最初の30秒で分かることを目指す。

試遊で1カテゴリだけを繰り返し変えていても問題ない。見たい変化を自分で選んでいる時間として扱う。全候補を見せるための強制チュートリアルは入れない。2回目は新しいパーツを解放するのではなく、同じパーツでも組み合わせで別の子ができることを楽しめるようにする。
